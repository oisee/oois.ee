Graded versus flat bias on an 8 GB card

i5: RTX 2070 8 GB, PCIe 3.0, full IQ2_XS 512 experts, expert cache 3.5 GB, pinned memory, -ub 512, no MTP. The graded bias is max(cap, ln(b / b_edge)) on the cold set: experts just below the hot-set edge are barely penalised, the deep tail gets the cap.

Graded versus flat at matched strength on 2×16 GB

i7: two RTX 4060 Ti 16 GB, full IQ3_S 512 experts, expert cache 17 GB, MTP drafts, -ub 512, pinned memory. Four arms in one session with flags identical to the reference run. The graded cap −1 has a mean penalty of −0.80, matching the flat −0.75, so the difference comes from the grading itself.

The price of the router bias

A bias changes which experts the router picks, so it changes the output. KL divergence measures how far the next-token distribution moves: full IQ3_S 512 with each bias file against the same model without bias, 7 held-out agent texts, 120,773 scored tokens, llama-perplexity on one 96 GB cloud GPU. Lower means closer to the unbiased model. The hard PB3-192 arm masks every expert outside the hot set, which is what pruning to 192 experts per layer does.

Cheaper cold experts: what each format costs

In a hot/cold split the 256 most-used experts per layer (PB3 top-256) stay in IQ3_S and the other 256 take a smaller format. KL against full IQ3_S 512 on the 3 texts that every variant finished (61,410 scored tokens), all on GPU. Size is the routed-expert bytes only.

Two-bank file on GPUs: first numbers

The two-bank file keeps 144 hot experts per layer in IQ3_S and the cold rest in Q2_0, 71.88 GB. It runs on i7 in two layouts: 16 + 8 GB, with the second card held to 7.6 GiB (peak 14,030 MiB on the first card and 7,366 MiB on the second), and 2×16 GB with MTP on the second card. MTP does not fit the 16 + 8 layout. The engine carries a fix for a crash on the first request that is not released yet. Speed: /completion, 2,000-token prompt, 128 greedy tokens, three servers × three runs interleaved, median, spread ≤0.4%. This is a different tool and prompt from the speed sections above, so the numbers do not compare with them.

Strata (fork) on i7

Strata (MIT) is a separate MoE inference engine with its own expert cache and a selection prior that steers the router toward a profile. Our local patch to it (PGO-SGB, not published) loads the same PB3 keep sets and the same graded bias. Same i7, same model pack, MTP spec 4, greedy, one 1,628-token ABAP prompt, 128 tokens, median of 3, arms interleaved. These numbers come from Strata's own runner and do not compare with the llama.cpp numbers above.

Gates pass: parity on both GPUs; an all-zero bias table gives the same 128 greedy tokens as no table (the single-card engine is not fully deterministic run to run, so this gate carries a caveat); a −inf bias on the top 3 experts changes routing in all 48 layers.

Strata: how far each arm moves the output

KL against Strata with no bias, 2 cards, 8 texts (16,884 positions per arm): ABAP code, an agent session, Russian prose, an English story, and the same UI text in Russian, German, Chinese and English. This is forced-window KL: comparable between arms, not the decode distribution. A self-check of the forced read against real decoding fails (same top token on 183 of 192 positions), so these values rank the arms in one scoring path and are not absolute. Floor: off against off is exactly 0. Negative control (top 3 experts banned): 0.239.

Arms: prior 1.5 is Strata's own profile with its selection prior. Graded, selection only applies graded cap −1 on PB3-192 to which experts are picked. Graded, damped weights also feeds the bias into the expert mixing weights. Residency only keeps PB3-192 resident with no bias.
